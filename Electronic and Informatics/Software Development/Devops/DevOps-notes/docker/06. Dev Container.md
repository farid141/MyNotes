# Dev Container

Ya, praktik yang umum memang **memisahkan image development dan image production**. Untuk bahasa yang melalui proses build seperti Node.js atau Go, image development biasanya **tidak menggunakan hasil compile**, sedangkan image production menggunakan hasil build yang sudah dioptimalkan.

## Node.js

Misalnya aplikasi Express.

### Development

Dockerfile:

```dockerfile
FROM node:22

WORKDIR /app

COPY package*.json ./
RUN npm install

CMD ["npm", "run", "dev"]
```

Docker Compose:

```yaml
services:
  app:
    build: .
    volumes:
      - .:/app
      - /app/node_modules
```

Kode di host di-mount ke `/app`, sehingga:

* VS Code melihat semua source code.
* IntelliSense bekerja.
* Perubahan file langsung terbaca.
* Biasanya menggunakan `nodemon` atau `vite` untuk hot reload.

### Production

Menggunakan multi-stage build:

```dockerfile
FROM node:22 AS builder

WORKDIR /app

COPY . .
RUN npm ci
RUN npm run build

FROM node:22-alpine

WORKDIR /app

COPY --from=builder /app/dist ./dist
COPY package*.json ./
RUN npm ci --omit=dev

CMD ["node", "dist/index.js"]
```

Di production hanya folder `dist` yang dibawa.

## Go

Development:

```dockerfile
FROM golang:1.24

WORKDIR /app

COPY go.mod go.sum ./
RUN go mod download

CMD ["go", "run", "main.go"]
```

atau menggunakan:

```bash
air
```

untuk hot reload.

Docker Compose:

```yaml
volumes:
  - .:/app
```

VS Code dapat membaca seluruh source.

---

Production:

```dockerfile
FROM golang:1.24 AS builder

WORKDIR /src

COPY . .
RUN go build -o app .

FROM gcr.io/distroless/static

COPY --from=builder /src/app /app

CMD ["/app"]
```

Image production hanya berisi binary.

## Lalu bagaimana dengan Dev Container?

Biasanya Dev Container **selalu menggunakan environment development**, bukan production.

Contohnya:

```bash
project/
├── .devcontainer/
│   └── devcontainer.json
├── docker-compose.yml
├── Dockerfile.dev
├── Dockerfile.prod
```

atau satu Dockerfile dengan target berbeda:

```dockerfile
FROM node:22 AS dev
...

FROM node:22 AS builder
...

FROM node:22-alpine AS production
...
```

Di `devcontainer.json`:

```json
{
    "dockerComposeFile": "../docker-compose.yml",
    "service": "backend",
    "workspaceFolder": "/app"
}
```

Service `backend` mengarah ke image development.

## Mengapa dipisah?

Kebutuhan development dan production memang berbeda:

| Development          | Production               |
| -------------------- | ------------------------ |
| Source code lengkap  | Hanya hasil build/binary |
| Debugger             | Tidak perlu              |
| Hot reload           | Tidak perlu              |
| Compiler & toolchain | Sebisa mungkin tidak ada |
| VS Code attach       | Tidak digunakan          |

Jadi ketika memakai Dev Container, anggap saja container tersebut adalah **mesin kerja (development workstation)**. Setelah selesai mengembangkan dan menguji aplikasi, pipeline atau Dockerfile production akan menghasilkan image yang jauh lebih kecil dan hanya berisi artefak yang diperlukan untuk menjalankan aplikasi. Ini juga mengurangi ukuran image, mempercepat startup, dan mengurangi permukaan serangan di lingkungan production.
