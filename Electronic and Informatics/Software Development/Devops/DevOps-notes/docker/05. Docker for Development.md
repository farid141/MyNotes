# Docker for Development

Idealnya proses `development` harus bisa memodifikasi code dan menambah library dengan instan. Oleh karena itu, kita menggunakan `bind-mount` daripada copy.

## Production Dockerimage

Sedangkan untuk `deployment`, tidak bisa karena di `Dockerimage` seluruh code sudah `dipindah ke image` yang dilakukan dengan command `COPY`. Hal ini dikarenakan pada umumnya proses CI/CD akan membuild di server CI dan nantinya `image build` akan dipull ke server production.

Kalau misal kita masuk ke container dan memodifikasi code di dalamnya, namun setelah container restart, modifikasi akan hilang.

### Using Production Image For Development

Image hasil build dari `Dockerimage Production` bisa kita gunakan untuk development. Gunakan `bindmount` directory host saat `akan menjalankan container` dari image tersebut agar `COPY . .` di dockerimage `teroverwrite`. Dan juga pastikan perintah menjalankan app nya agar `autoreload`.

## Unresolved Dependency

Ketika kita install dependency di container dan host tidak dapat mengaksesnya, saat development code di host (karena kita pakai `bind-mount` code) akan terjadi unresolved import. Untuk handle hal ini, dapat menggunakan extensi `Dev Container` di vscode.

### Dev Container

Editor akan berjalan menggunakan interpreter Python di dalam container sehingga:

- autocomplete bekerja
- import resolve
- linting benar
- debugger langsung memakai environment container

Misalnya:

```Dockerfile
docker-compose.yml
.devcontainer/
    devcontainer.json
```

```json
// devcontainer.json
{
    "name": "My App",
    "dockerComposeFile": "../docker-compose.yml",
    "service": "app",
    "workspaceFolder": "/workspace"
}
```

Setelah Reopen in Container, warning import biasanya hilang.
